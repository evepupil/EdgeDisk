# 搜索与治理

- **模块定位**：提供跨目录检索、全局分享管理和导入任务控制。
- **对应代码**：`src/server/search-query.ts`、`src/server/services/search-service.ts`、`src/server/repos/file-index-repo.ts`、`src/server/services/import-task-status.ts`、`src/server/services/import-service.ts`、`src/server/shares.ts`、`app/client/dashboard/`
- **所属 M 里程碑**：[M3](../roadmap.md#m3)
- **当前状态**：已完成
- **最近更新时间**：2026-08-07

## 职责与边界

该模块负责需要新增服务端能力的管理功能。当前目录即时筛选属于 M1，目录分页属于 M2，全盘检索属于本模块。

三块内容：导入任务控制、全局分享治理、全盘搜索。

## 结构与数据流

导入任务的状态流转规则单独放在 `import-task-status.ts`，只有纯判断函数，不碰 D1；`import-service.ts` 负责实际的状态写入和队列交互。分享治理直接枚举 KV，不额外建索引。全盘搜索计划用 D1 建文件索引。

## 关键决策

- 在明确 R2 对象规模和查询频率后再选择搜索索引方案。
- 全局分享列表通过 KV 游标枚举实现，不额外建索引。KV 的 `list({prefix})` 本身就是可靠的全量枚举，多一份索引就多一份漂移风险。
- 任务取消区分排队中和执行中两种语义（见下）。

## 当前实现

### 导入任务控制（已完成）

新增 `canceled` 状态。`import_tasks.status` 是不带约束的 TEXT 列，所以加状态值不需要迁移。

状态流转：

```
queued ──> running ──> succeeded
  │          │     └──> failed ──┐
  │          │                   │
  └──────────┴──> canceled <─────┘   failed / canceled 可以重新回到 queued
```

**取消分两种语义**，这是本次最需要说清楚的地方：

- **排队中取消是干净的**：直接把状态写成 `canceled`，消费者拿到消息时通过 `shouldSkipImportMessage` 看到终态，直接 ack 丢弃，不会开始下载。
- **执行中取消只能尽力而为**：正在飞的 `fetch` 无法中断。消费者在下载完成后会回查任务状态，发现已被取消就把刚写进 R2 的对象删掉再 ack。所以界面上会明确提示「正在下载的部分会在结束后回滚」，不假装已经立刻停下。
- 下载失败的分支同样先回查状态，避免把 `canceled` 覆盖成 `failed` 或重新入队——否则用户点了取消，任务还会自己爬回队列。

**重试**只对 `failed` 和 `canceled` 开放：`succeeded` 重试没意义，`queued` / `running` 重试会造成重复下载。重试会把 attempts 归零后重新入队；入队失败时把状态还原成 `failed`，否则任务会永远停在「排队中」等一条不存在的消息。

**清空已结束任务**：`DELETE /api/import-tasks` 删掉所有终态任务，否则任务列表只会越来越长。

接口：

- `POST /api/import-tasks/cancel`，body `{ id }`
- `POST /api/import-tasks/retry`，body `{ id }`
- `DELETE /api/import-tasks`

### 全局分享治理（已完成）

新增侧边栏「分享管理」面板，集中查看和撤销所有分享，支持多选批量撤销。

**没有为此新建索引**。`listAllShares` 直接用 KV 的 `list({ prefix: 'share:' })` 加游标翻页。KV 的前缀枚举本身就是可靠的全量视图，再维护一份索引只会多一份漂移来源。默认一页 200 条，超出时界面明确说明只显示了前 200 个。

由于 KV 的 `put` 没有用 `expirationTtl`，过期判断一直在应用层做。`isExpiredShare` 把这个判断收敛成一个纯函数，所有读路径共用；分享列表读到过期记录会顺手清掉并在状态栏汇报清理数量。时间字段损坏时按「未过期」处理，宁可留着也不误删用户的分享。

**顺带修掉一处性能问题**：`retargetSharesForMove` 以前每次移动都全量扫 `share:` 键空间，KV 读取次数等于系统里的分享总数，哪怕被移动的路径根本没有分享。现在改走已有的 `share-target:` 反向索引，和 `revokeSharesForPath` 共用 `shareTargetSearchPrefixes`。

反向索引能覆盖子孙路径的原因：路径经过 `encodeURIComponent` 编码后，`A/` 变成 `A%2F`，嵌套的 `A/b/c.txt` 变成 `A%2Fb%2Fc.txt`，仍然以 `A%2F` 开头，所以去掉结尾的 `|` 做前缀查询就能一并覆盖。兄弟目录 `Ax/` 编码成 `Ax%2F`，不会被误命中。

接口：

- `GET /api/shares/all?cursor=&limit=`
- `POST /api/shares/revoke-batch`，body `{ codes: string[] }`

### 全盘搜索（已完成）

用 D1 表 `file_index` 做 R2 对象的可查询镜像（迁移 `0003_file_index.sql`）。

**只索引文件，不索引文件夹**。文件夹是隐式前缀，索引它需要从每个文件路径推导所有父级，删除时的孤儿清理成本很高。搜文件夹留作待扩展项。

**索引漂移是这个方案的主要风险**：任何一处写 R2 却漏更新索引，搜索就会静默少东西或多东西——和目录列表被截断是同一类问题（看起来正常，实际不全）。两条纪律控制它：

1. 所有索引改动只经过 `src/server/repos/file-index-repo.ts` 一个模块，不在业务代码里散写 SQL。
2. `POST /api/search/reindex` 从 R2 全量重建，兼作存量数据的首次回填。分页进行，一次请求最多扫 20 页，返回游标供继续；`cursor` 为空表示从头开始并先清空旧索引。

目前覆盖的写入点：

| 位置 | 索引动作 |
| --- | --- |
| `putDirectObject`（小文件直传） | upsert |
| `completeMultipartUpload`（分片上传完成） | upsert |
| `importFromUrl`（URL 导入成功） | upsert |
| `moveObject` 文件分支 | 删旧 + upsert 新 |
| `moveObject` 文件夹分支 | 按前缀删旧 + 批量 upsert 新 |
| `moveToTrash` | 删除（按路径或前缀） |
| `restoreTrashItem` | 重新 upsert |
| `permanentlyDeleteTrashItem` | 无需处理，进回收站时已经删过 |
| `createFolder` | 不索引，占位标记是内部实现 |

`isIndexableKey` 统一判断哪些键不该进索引：回收站前缀下的对象（已经删掉的文件出现在搜索结果里会让人以为它还在原处）、文件夹占位标记、目录形态的键。`TRASH_PREFIX` 带结尾斜杠，所以用户自己创建的 `__edgedisk_trashcan/` 不会被误伤。

上传完成后，R2 是文件内容的真实来源，`file_index` 只是可恢复的查询镜像。直传和分片合并都会尝试写入索引；如果 D1 表尚未迁移或暂时不可用，上传仍然成功，之后通过 `reindex` 补齐索引。

**大小写不敏感匹配**靠单独的 `name_lower` 列，因为 SQLite 的 `LIKE` 只对 ASCII 做大小写折叠。查询关键词统一转小写后与该列比较。

**LIKE 通配符必须转义**：`%` 和 `_` 在 LIKE 里是通配符，用户搜「100%」如果不转义会退化成「以 100 开头的任何东西」。`escapeLikePattern` 先转义反斜杠本身再转义通配符，配合 SQL 的 `ESCAPE '\'` 声明。这段逻辑放在 `search-query.ts` 且有单测覆盖——转义写错会让搜索结果悄悄变错，不会报错。

**存储用量统计**顺带由索引提供：`GET /api/storage` 返回文件数和总字节数，侧边栏那根原来是装饰的进度条现在显示真实数字。R2 没有配额概念，所以没有「用了百分之几」可言，进度条只表示已统计。

接口：

- `GET /api/search?q=&limit=&offset=`
- `GET /api/storage`
- `POST /api/search/reindex?cursor=`

界面上顶部搜索框新增「全盘」开关：关闭时是原来的当前目录即时筛选（纯浏览器端），打开时走服务端索引并对输入做 300ms 防抖。搜索结果行会显示文件所在目录，否则同名文件无法区分。

## 验证方式

- `src/server/services/import-task-status.test.ts` 覆盖状态流转：取消与重试的适用状态、两者互斥、除 `succeeded` 外每个状态都有可用操作、消费者跳过条件。
- `src/server/shares.test.ts` 覆盖过期判断（含损坏时间字段）和移动后的分享路径改写：单文件精确匹配、文件夹连带子孙、同名前缀兄弟目录不误伤。
- `src/server/search-query.test.ts` 覆盖 LIKE 通配符转义（`%`、`_`、反斜杠本身）、关键词清洗、分页参数裁剪。
- `src/server/services/search-service.test.ts` 覆盖索引准入判断：回收站对象、占位标记、目录形态键被排除，名字相似的普通目录不受影响。
- `npm run check` 与 `npm run build`。
- 队列消费者、KV 枚举和 D1 查询的实际行为依赖运行时，不写单测。索引同步是否真的没有漏点，需要在真实环境用 reindex 前后的文件数对比来验证。

## 部署注意

新增的 `file_index` 表需要先执行迁移。`wrangler.jsonc` 已配置 `migrations_dir`，优先使用迁移追踪命令：

```bash
npx wrangler d1 migrations apply edgedisk --remote
```

发布 Worker 前要确认迁移已经应用；如果只发布代码而漏掉 `0003_file_index.sql`，上传内容仍会写进 R2，但全盘索引无法即时更新。

存量数据不会自动进索引，迁移后要调一次 `POST /api/search/reindex` 做回填。返回 `done: false` 时带上返回的 `cursor` 继续调，直到 `done: true`。
