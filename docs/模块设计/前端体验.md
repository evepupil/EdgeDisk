# 前端体验

- **模块定位**：提供后台文件管理与公开分享的页面结构、视觉系统和浏览器交互。
- **对应代码**：`app/components/`、`app/client/`、`app/styles/`、`app/routes/_renderer.tsx`
- **所属 M 里程碑**：[M1](../roadmap.md#m1)、[M2](../roadmap.md#m2)
- **当前状态**：已完成
- **最近更新时间**：2026-07-26

## 职责与边界

该模块负责页面导航、目录展示、搜索与排序、选择状态、上传反馈、详情抽屉、表单弹窗、媒体预览、导入任务、回收站和分享页体验。文件持久化、权限和接口校验由服务端模块负责。

## 结构与数据流

Honox 路由输出页面骨架，生产环境加载 Vite 生成的独立客户端入口，开发环境加载 TypeScript 源入口。客户端代码按共享工具、后台控制器、后台视图和分享页控制器拆分，通过类型明确的 API 封装读取数据，再更新对应页面区域。浏览器资源构建到 `dist/static/`，由 Cloudflare Workers Static Assets 发布；Worker 服务端包保留在 `dist/index.js`。

## 关键决策

- 采用顶部栏、侧边导航和主工作区的紧凑布局。
- 详情按需显示在右侧抽屉，文件列表保持主视觉焦点。
- 列表行只保留三点操作菜单，批量操作通过选择栏出现。
- 浅色与深色主题沿用确认原型的语义化设计变量、控件尺寸和响应式断点。
- 使用 Lucide 图标，移除 emoji 图标和含糊的纯图标操作。
- 当前目录搜索与排序在浏览器完成；全盘搜索留给 M3。
- 目录翻页对用户不可见：第一页到手就渲染保住秒开手感，剩余页在后台补齐后整体重绘一次，避免每页都全量重建 DOM。设页数上限兜底，触顶时明确告知只载入了前 N 项，不假装已经全部显示。

## 当前实现

后台采用确认原型中的紧凑顶栏、侧边导航和无卡片主工作区，支持文件列表与网格切换、当前目录搜索和排序、多选批量操作、详情抽屉、上传状态、URL 导入任务、回收站及结构化弹窗。公开分享页沿用原型的带边界平铺结构，提供分享信息、面包屑、文件多选下载和音视频预览。两套页面共享图标、格式化、DOM 与 API 工具，客户端入口已移除 `@ts-nocheck` 并通过严格 TypeScript 检查。

生产构建将后台和分享页入口拆成 `/dashboard.js` 与 `/share.js`，共享代码由 Vite 自动分块。Wrangler 仅发布 `dist/static/` 里的浏览器资源，避免公开 Worker 服务端包。

### 目录分页（M2）

后台目录和公开分享目录共用 `app/client/shared/paging.ts` 的 `collectPages`：拿到第一页后沿着游标把剩余页拉完，合并进同一份数据。两个要点：

- **页数上限**：默认最多自动拉 20 页（约两万项），触顶后在状态栏说明只载入了前 N 项，提示进入子目录查看其余内容。
- **加载世代**：每次切目录自增一个计数器，`collectPages` 每轮检查是否已经切走。切走后立即停手并标记 `stale`，结果整个丢弃——否则上个目录剩余页的文件会混进新目录的列表里。

### 上传体验（M2）

旧实现把所有选中文件塞进一个 FormData 一次 POST，进度条是写死的 32% 跳 100%，没有取消也没有重试。现在由 `app/client/dashboard/uploader.ts` 接管：

- **真实进度**：请求走 XHR 而不是 `fetch`，因为 `fetch` 拿不到上传进度事件。进度按字节统计，界面显示百分比、已传/总量、速度和剩余时间。
- **分片记账**：每片单独记已传字节，某一片重试时不会把整体进度算重。
- **并发**：默认同时传 2 个文件，单文件内同时传 3 片。调度由 `app/client/shared/concurrency.ts` 的 `runWithConcurrency` 负责。
- **重试**：网络错误、5xx 和 429 自动退避重试 3 次；4xx 是请求本身有问题，直接失败不浪费时间。
- **取消**：掐掉所有在飞的 XHR，并对已经建立的分片会话逐个调 `abort`，避免残片留在 R2 里计费。
- **刷新时机**：只要有文件落地就刷新目录，取消和部分失败同样要让用户看到已经传上去的那部分。

切片计划、剩余时间和速度换算都在 `app/client/shared/upload-plan.ts`，是纯函数，单测覆盖。

## 验证方式

- 纯函数测试覆盖筛选、排序、格式化和路径处理。
- `npm run check` 验证严格 TypeScript。
- `app/client/shared/paging.test.ts` 覆盖分页收集：单页短路、多页顺序合并、页数上限、切目录后丢弃结果。
- `app/client/shared/upload-plan.test.ts` 覆盖切片计划（首尾相接、完整覆盖、末片偏小、其余等大）与速度、剩余时间、百分比换算。
- `app/client/shared/concurrency.test.ts` 覆盖并发上限、退避重试次数与放弃条件。
- 上传引擎本身依赖 XHR 和真实网络，不写单测；由手工上传大文件验证进度、取消和重试。
- `npm run build` 验证 Honox 客户端资源和 Worker 产物。
- `npx wrangler deploy --dry-run` 验证 Worker 与静态资源发布配置。
- 直接请求构建后的 Worker，确认后台和分享页均返回 200，且加载各自的生产客户端入口。
- 视觉布局由桌面与移动视口人工检查，不为纯样式编写单元测试。
